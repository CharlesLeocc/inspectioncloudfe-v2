# 交互与数据安全规范

## 1. 适用范围

本规范适用于可能发生数据丢失、重复操作、异步竞态或不可逆变更的页面，包括：

- 新增和编辑表单。
- 多步骤配置。
- 图片、地图和 3D 标注。
- 拖拽排序与批量编辑。
- 文件上传、导入、导出和报告生成。
- 自动保存、轮询和长任务。
- 团队、项目、任务、模型、图片和当前对象切换。

## 2. 脏数据模型

### 2.0 术语约定

- **持久化基线**：最近一次成功从服务端加载或保存成功的数据快照。
- **业务性变化**：会改变提交结果、排序、标注、配置或任务状态的变化。
- **等效守卫**：在没有 Router 的场景下，对团队、项目、任务、弹窗或当前对象切换执行同一确认逻辑的机制。
- **页面实例仍有效**：组件仍处于可写状态，所属路由、业务上下文和请求版本均未失效。
- **一次性放行**：用户确认放弃后只允许当前一次导航或切换，完成、取消或失败后自动恢复拦截。

### 2.1 定义

脏数据是指当前可提交业务数据与最近一次成功持久化基线不一致。以下行为都可能产生脏数据：

- 新增、修改或删除字段。
- 排序、勾选和批量配置。
- 标注点、测量值、模型姿态和视图参数发生业务性变化。
- 上传文件已加入待提交队列。
- 多步骤表单中任一步骤的数据被修改。

UI 展开状态、hover、临时焦点等不参与提交的数据不应导致脏状态。

### 2.2 基线与比较

- 数据加载成功或保存成功后建立新的持久化基线。
- 只规范化和比较真正参与提交的字段。
- 对大对象不得在每次输入时执行完整 `JSON.stringify` 或深拷贝。
- 大表单可以在输入事件中直接标记脏状态，在离开或重置时按需精确比较。
- 排序和标注等结构化数据应使用稳定 ID，避免仅因引用或无关字段变化误判。

### 2.3 统一状态

项目统一脏数据守卫应落在 `src/composables/useUnsavedChangesGuard.js`，并至少暴露：

```js
{
  isDirty,
  markDirty,
  resetBaseline,
  confirmDiscard,
  allowNextLeave,
}
```

`isDirty` 是页面是否存在未持久化变更的唯一判断来源，禁止不同关闭入口维护各自的布尔值。

- 已存在该 composable 时必须复用，不得在页面内复制另一套守卫。
- 尚未落地且当前任务需要脏数据保护时，应在用户授权范围内优先建立该统一能力；修改范围不包含公共能力时，先说明依赖并请求处理方式。
- `allowNextLeave` 只放行下一次已确认的离开，路由完成、取消或失败后必须自动复位。
- 无路由变化的团队、项目、任务和当前对象切换通过 `confirmDiscard` 使用同一确认逻辑。

## 3. 离开与切换确认

### 3.1 SPA 路由离开

- 存在脏数据时必须使用 `onBeforeRouteLeave` 或等效守卫。
- 无脏数据时禁止弹出确认。
- 用户确认放弃后只放行当前一次导航，不能永久关闭守卫。
- 用户取消时保持当前路由、表单数据和编辑状态。
- 保存成功触发的程序化导航应在更新基线后执行。

### 3.2 浏览器刷新和关闭

- 存在脏数据时注册 `beforeunload`，无脏数据时移除。
- `beforeunload` 只用于刷新、关闭标签页和浏览器导航兜底。
- 浏览器不保证显示自定义文案，不得依赖自定义弹窗内容。
- 组件卸载时必须移除监听。

### 3.3 无路由变化的上下文切换

切换以下对象前必须执行同一脏数据检查：

- 团队、项目和任务。
- 报告模板和配置步骤。
- 标签页、当前模型、当前图片和当前病害。
- 弹窗内部选中对象。

禁止只依赖路由守卫，因为这些操作可能不会改变 URL。

### 3.4 弹窗关闭

关闭按钮、取消按钮、遮罩点击、ESC 和父组件控制关闭必须汇合到同一个关闭函数。提交中默认禁止关闭；存在脏数据时先确认放弃。

## 4. 多步骤表单

- 切换步骤前完成当前步骤必要校验。
- 前置数据改变并导致后续结果失效时，必须明确重置受影响步骤。
- 禁止保留与新条件不一致的旧计算结果或旧接口响应。
- 最终提交成功前，不得提前清空步骤状态。
- 返回上一步不能无意触发重复请求或重置已填写内容。
- 步骤离开确认和页面离开确认共享同一脏状态来源。

## 5. 防重复提交

所有产生服务端副作用的操作必须防止重复触发，包括新增、修改、删除、导入、导出、上传和生成报告。

```js
if (isSubmitting.value) return

isSubmitting.value = true
try {
  await submit()
} finally {
  isSubmitting.value = false
}
```

- 请求期间禁用或锁定所有等价触发入口。
- 防抖不能替代提交锁。
- 需要时使用后端幂等标识。
- 请求失败时必须恢复交互状态。
- 保存成功后先更新本地数据和脏状态，再执行关闭或导航。

## 6. 请求竞态

### 6.1 旧请求取消

搜索、筛选、分页、联动选择和业务上下文切换时，优先使用 Axios `signal` 取消旧请求。

- 被取消的请求不显示错误提示。
- 页面卸载时取消仍在执行且结果无意义的请求。
- 同一控制器不得错误复用于无关请求。

### 6.2 旧响应隔离

无法取消或请求已经到达服务端时，响应写入状态前至少校验一种上下文：

- 请求序号仍为最新。
- 项目、任务或对象 ID 未变化。
- 路由和页面实例仍有效。

禁止将旧项目或旧对象的响应写入新上下文。

所有可能竞态的异步状态写入必须满足以下门槛：

```js
const requestId = ++latestRequestId
const contextId = currentContextId.value
const result = await request()

if (requestId !== latestRequestId || contextId !== currentContextId.value) return
data.value = result
```

版本号、请求 ID 和上下文 ID 可以按场景选择，但不能只依赖请求完成顺序。

### 6.3 加载状态

- 首次加载与后台刷新使用不同状态。
- 并发请求不能通过单个布尔值互相提前关闭 loading。
- 可以使用计数器、请求 ID 或独立状态管理并发 loading。
- loading 计数由创建并发请求的 composable 或 service 持有，请求必须在 `finally` 中只释放自己占用的一次计数。
- 空数据、筛选无结果、失败和无权限必须显示不同状态。

## 7. 自动保存

- 自动保存必须进行防抖或合并，但不能与手动保存并行覆盖。
- 自动保存开始前记录版本或请求序号。
- 自动保存失败不能清除脏状态。
- UI 必须区分保存中、已保存和保存失败。
- 页面离开时若仍在保存，必须等待、取消或提示风险。
- 同一字段的新值不能被较早的保存响应覆盖。

## 8. 删除、覆盖和乐观更新

### 8.1 不可逆操作确认

删除、覆盖、清空、重置、重新生成和放弃未保存数据时，确认内容必须说明：

- 操作对象。
- 操作范围。
- 是否可恢复。
- 对后续数据或任务的影响。

禁止只显示“是否确认”而不说明影响。

### 8.2 乐观更新

- UI 先更新时必须保存可恢复快照。
- 请求失败必须回滚并提示。
- 排序保存失败时恢复原顺序。
- 部分成功时只回滚失败部分。
- 禁止接口失败但 UI 仍显示成功状态。

## 9. 批量操作

- 必须区分全部成功、部分成功和全部失败。
- 结果应包含成功数量、失败数量和失败项原因。
- 成功项不得因其他项失败被错误恢复为未处理。
- 失败项应支持重试或导出失败清单。
- 大批量操作应限制并发，避免一次创建过多请求或响应式更新。

## 10. 上传、下载与长任务

### 10.1 文件选择

上传前校验文件数量、大小、扩展名、MIME、空文件、重名策略和业务类型。前端校验不能代替后端校验。

### 10.2 上传中离开

- 离开前说明上传是否会终止。
- 可取消任务必须提供取消入口。
- 取消后终止 Axios、文件读取、Worker 和分片调度。
- 组件卸载后不得继续更新进度。
- 同一文件不得因重复点击被无意上传多次。

### 10.3 长任务

- 报告生成、模型转换等任务使用服务端任务 ID 表示真实状态。
- 页面刷新后应能按任务 ID 恢复进度。
- 轮询必须可停止、可超时，并在页面隐藏时降频。
- 完成、失败和取消后必须终止轮询。
- 页面组件不得成为长任务状态的唯一来源。

## 11. KeepAlive 与组件生命周期

- `onDeactivated` 暂停轮询、动画、渲染和只服务于可见页面的监听。
- `onActivated` 根据当前上下文恢复必要任务，并检查数据是否已过期。
- 真正卸载时取消请求并释放不可恢复资源。
- 缓存页面不得在后台持续高频更新 DOM 或 60 FPS 渲染。

## 12. 验证场景

涉及本规范的改动至少验证：

1. 无修改直接离开，不弹窗。
2. 修改后取消离开，数据仍保留。
3. 修改后确认离开，只放行一次。
4. 保存成功后离开，不弹窗。
5. 刷新或关闭标签页时触发浏览器确认。
6. 项目、任务或当前对象切换时执行相同检查。
7. 连续提交不会产生重复请求。
8. 快速切换查询条件时旧响应不会覆盖新结果。
9. 上传或长任务离开时按设计取消或继续。
10. 组件卸载后不再更新状态或产生错误提示。
